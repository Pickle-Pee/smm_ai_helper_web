# SMM AI Helper — дизайн-система v1

> Статус: первая версия (`feat/brand-design-v1`). Все данные демонстрационные, интерфейс работает только с локальным состоянием.

## 1. Концепция: «рабочий стол маркетолога»

SMM AI Helper — не чат с моделью, а рабочая среда, в которой AI — один из инструментов. Поэтому в центре интерфейса находятся **бренды, результаты и документы**, а диалог с AI — способ их получить.

Три принципа:

1. **Тихий холст, уверенная навигация.** Светлый холст `#F3F5F9`, белые рабочие поверхности и глубокий navy-сайдбар. Контент читается спокойно, навигация задаёт каркас.
2. **Цвет — это смысл, а не декор.**
   - **Бирюзовый** — действия человека и прогресс: основная кнопка, активный пункт, фокус, «готово».
   - **Фиолетовый** — всё, что создаёт или делает AI: кнопка отправки AI-запроса, метка `AI`, левая грань AI-результатов.
   - Пользователь всегда видит, где его материал, а где сгенерированный.
3. **Честность состояния.** Нереализованные возможности отмечены значком «Скоро» или «Недоступно в демо». Интерфейс не изображает успешную работу бэкенда: отправленный запрос сохраняется локально и помечается «AI не подключён».

## 2. Палитра

Базовые цвета бренда сохранены, к ним добавлены шкалы и проверенные на контраст оттенки для текста.

| Роль | Токен | Значение | Применение |
| --- | --- | --- | --- |
| Navy (бренд) | `--navy-800` | `#15253D` | сайдбар, основной текст, hero |
| Navy глубокий | `--navy-900` | `#0F1C30` | фон под логотипом, оверлеи |
| Бирюзовый (бренд) | `--teal-500` | `#19B6AE` | заливка основной кнопки (текст navy, контраст 6.1:1) |
| Бирюзовый текст | `--teal-700` | `#0A6E6A` | ссылки, статус «готово» на белом (5.9:1) |
| Фокус | `--teal-600` | `#0B7F7A` | кольцо фокуса (4.8:1 к белому) |
| Фиолетовый AI | `--violet-500` | `#7568DF` | AI-грань, иконки AI |
| AI-кнопка | `--violet-600` | `#5F52D0` | заливка AI-кнопки (белый текст 5.8:1) |
| Вторичный текст | `--gray-600` | `#55637A` | описания (6.0:1) |
| Приглушённый текст | `--gray-500` | `#5F6C82` | метаданные (5.3:1 на белом, 4.9:1 на холсте) |

Важное решение: основная кнопка — **бирюзовая заливка с navy-текстом**, а не с белым. Белый на `#19B6AE` даёт лишь 2.5:1, navy — 6.1:1, и такая кнопка становится узнаваемой частью бренда.

Статусы используют те же семейства: «Готово» — бирюзовый, «Требует проверки» — янтарный, «Ошибка» — красный, «Черновик» — нейтральный.

Цвета брендов (монограммы проектов) — шесть приглушённых тонов, гармонирующих с navy: бирюзовый, фиолетовый, коралловый, янтарный, синий, зелёный.

## 3. Типографика

- Гарнитура **Onest** (Google Fonts, переменная, 400–700) — спроектирована с учётом кириллицы, хорошо держит мелкие кегли интерфейса и плотные заголовки.
- Цифры — `font-variant-numeric: tabular-nums` в таблицах, счётчиках и датах.
- Шкала: 12 / 13 / 14 (основной) / 15 / 17 / 20 / 24 / 30 px. Заголовки — 600–650, трекинг `-0.02em`.
- Строки длинных текстов AI-ответов ограничены ~72 символами.

## 4. Композиция и сетка

- Шаг отступов — 4 px (`--space-1` … `--space-16`).
- Контейнер страниц — до 1280 px, поля 32 / 24 / 16 px.
- Брейкпоинты: **≥1280** — полный сайдбар и три колонки в AI Workspace; **1024–1279** — полный сайдбар, контекст бренда в выезжающей панели; **768–1023** — компактный сайдбар с иконками, история и контекст в панелях; **<768** — нижняя таб-навигация, однопоточный layout.
- Радиусы: 8 (контролы), 12 (карточки), 16–20 (крупные панели). Карточки отделяются границей, тени — только у всплывающих слоёв.

## 5. Компонентная система

Базовые компоненты (`components/ui`):

| Компонент | Назначение |
| --- | --- |
| `Button`, `ButtonLink`, `IconButton` | варианты `primary`, `secondary`, `ghost`, `ai`, `onDark`; размеры `sm`/`md`/`lg` |
| `Badge` | тоны `neutral`, `accent`, `ai`, `success`, `warning`, `danger`, `info`, значок «Скоро» |
| `Card`, `CardHeader` | поверхность с заголовком, описанием и действием |
| `Field`, `Input`, `Textarea`, `Select`, `SearchField` | формы с подписью, подсказкой и ошибкой |
| `SegmentedControl` | переключатель на нативных radio — клавиатура из коробки |
| `Tabs` | ARIA-вкладки с навигацией стрелками |
| `Dialog` (`modal`/`sheet`) | на нативном `<dialog>`: ловушка фокуса, Esc, затемнение |
| `EmptyState`, `ErrorState`, `Skeleton` | обязательные состояния каждого списка |
| `Monogram` | цветная плитка бренда |
| `PageHeader`, `Toast` | заголовок страницы, уведомления в `aria-live` |

Фирменные элементы:

- **Логотип** — navy-плитка с бирюзовой линией роста и фиолетовой «искрой» AI.
- **AI-грань** — 3 px фиолетовая линия слева у любого сгенерированного результата.
- **Брифинг** — navy-блок на рабочем столе с полем запроса к AI и сценариями.
- **Миниатюры документов** — схематичные превью по типу файла (таблица, документ, PDF, слайд, карточка), чтобы список читался без чтения расширений.

## 6. Состояния

Каждый раздел, загружающий данные, поддерживает: загрузку (скелетоны той же формы, что и контент), пустое состояние с действием, ошибку с повтором, пустой результат поиска со сбросом фильтров и длинный контент (обрезка в одну–две строки с полным текстом в `title`, перенос длинных слов).

Для проверки состояний в **Настройки → Демо-состояния** можно принудительно включить загрузку, пустые данные или ошибку во всех разделах.

## 7. Доступность

- Видимое кольцо фокуса на всех интерактивных элементах, ссылка «Перейти к содержимому».
- Контраст текста ≥ 4.5:1, некстовых элементов ≥ 3:1.
- Семантика: `nav`, `main`, `header`, заголовки по уровням, `aria-current` в навигации, `aria-live` для уведомлений и новых сообщений.
- Глобальный поиск — ARIA combobox (`Ctrl/⌘ + K`), вкладки — стрелки/Home/End, диалоги — Esc и возврат фокуса.
- `prefers-reduced-motion` отключает анимации.

## 8. Архитектура данных

```
lib/api/contracts.ts   — типизированные интерфейсы API (ProjectsApi, ThreadsApi, DocumentsApi)
lib/api/mock-client.ts — mock-адаптер на демонстрационных данных
lib/api/index.ts       — точка подключения: заменить mock на HTTP-клиент после утверждения Web API
features/*/model.ts    — чистые редьюсеры и селекторы (покрыты тестами)
features/*/store.tsx   — провайдеры состояния, раздельные для проектов, AI Workspace, документов и аккаунта
```

Компоненты получают данные только через хуки фич, поэтому замена адаптера не требует переписывания UI.
